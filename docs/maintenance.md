# Maintaining and validating the documentation

[Documentation home](README.md)

The tutorials are hand-written Markdown. The API reference is generated from
source signatures and docstrings, and the illustrations are generated by the
library. No documentation hosting service or special Markdown build is needed.

## Rebuild

From the repository root with dependencies installed:

```bash
python -m docs.examples.gallery
python -m docs.examples.recipes
python -m docs.tools.render_examples
python -m docs.tools.build_reference
python -m docs.tools.check_docs
python -m unittest discover -s tests -v
```

The `-m` form works from the checkout without requiring an editable install;
Python still needs the NumPy/PyMuPDF dependencies. After `pip install -e .`,
you may also use the direct script commands shown in the guide.

Paired example illustrations are generated directly from marked Markdown code
blocks by [render_examples.py](tools/render_examples.py). Run
`python -m docs.tools.render_examples --latex` to also rebuild the checked-in
math figures (pdflatex and Inkscape required). Each snippet runs in a temporary
directory, and its saved SVGs receive a page prefix under `docs/figures/`.
Edit the snippet and rebuild its figure together; do not maintain a separate
approximation of the example in the gallery script. Only explicitly marked,
repository-authored code is executed.

The gallery writes 14 core SVGs (including the reusable icon) and recipes
write 3 more. API generation writes five Markdown pages under `docs/api/`.
The checker validates local links/anchors, fenced Python syntax, package
export/method coverage in the reference, docstring coverage, and SVG XML/ID
references. It also checks that the reference matches current source output.

To rebuild examples as part of the check:

```bash
python -m docs.tools.check_docs --run-examples
```

Small guide snippets that depend on prior variables, user font files, IPython
or external executables are syntax-checked; the complete core gallery and
recipe scripts are executable integration examples. The checker does not
automatically execute arbitrary Markdown snippets or optional integrations.

## Optional integrations

Run these explicitly after configuring Inkscape/TeX:

```bash
python -m docs.examples.optional_integrations export
python -m docs.examples.optional_integrations latex --backend inkscape
# If those backends are installed:
# python -m docs.examples.optional_integrations latex --backend dvisvgm
# python -m docs.examples.optional_integrations latex --backend pdf2svg
```

They write `export.svg`, `export.png`, `export.pdf`, or `latex.svg` under
`docs/figures/`. The latex command replaces the same output file for different
backends. The pre-rendered `latex.svg` illustration is checked in; the export
smoke-test outputs are ignored by Git. External programs are needed only to
regenerate the optional outputs, not to view the documentation.

## Review figures and changes

Open generated SVGs in a browser or SVG editor. Check for clipped titles,
overlapping labels, legible legends, stray arrows and enough margins.
An XML parse or a passing code example cannot establish visual quality.

When changing an API, update the docstring, rebuild the reference, and update
the explanatory guide and runnable example together. Avoid documenting a
desired behavior as if it were already implemented. In particular, preserve
the documented unit distinctions, append-only drawing behavior, and known
limits until their implementations actually change.

Core documentation changes should not require rebuilding distributions or
publishing a release. The root [README](../README.md) contains packaging and
release instructions. The broad root ignore rule is intentionally overridden
for `docs/`; keep generated caches and optional binary outputs ignored.
